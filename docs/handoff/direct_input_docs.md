정리: Claude(Cowork) · 결정권자: 김주완 · 공통 규칙은 저장소 맨 위 `CLAUDE.md`

## 0. 왜 하는가

기획서 위험 항목 "지갑 밖 서류 14개 항목: 직접 입력 + 서류 칸 안내 + '직접 입력 기준' 표시"를 화면에 구현한다.
데이터 정의는 끝났다(주완 작성 확인서류표). 2026-11-16 기준 `fix/front-code-v3`(0037c4b)에는 이 화면이 없다. 전자지갑 서류는 3종뿐이고, 항목별 서류 안내와 직접 입력 칸이 없다.

## 3. 화면 요구사항

1. **정책 상세 > '공고 기준과 나의 조건'** 아래에 "직접 입력이 필요한 조건" 영역을 추가한다. 그 정책에 해당하는 항목만 보여준다.
   - 항목마다: 입력 칸, "직접 입력 기준" 표시, 확인할 서류 이름, 서류에서 볼 내용("서류에서 확인하는 내용"), 발급 경로("발급·확인 경로"), 주의사항("한계·주의사항")
   - 입력 결과는 판정 규칙이 연결되기 전까지 `?`(직접 입력 기준, 규칙 연결 전)로 표시한다. **규칙이 없는 상태에서 O/X를 만들지 않는다.**
2. **전자지갑 화면**에 "지갑 밖 서류(직접 준비)" 목록을 추가한다. 14종 각각 발급기관·발급 경로·확인 가능한 내용·한계를 보여주고, 기존 지갑 연계 서류와 구분한다.
3. **시연 정책과 항목 연결(제안, 주완 확인)**:
   - 1 주거(월세·임차보증금): 44, 45, 48, 52, 53
   - 2 취업 지원: 31, 34, 52, 53
   - 3 교육·자격: 52, 53
   - 4 청년미래적금: 31, 52, 53
   - 8 면접정장 대여: 34
   - 학자금 항목(21, 22, 23, 54)을 보여줄 시연 정책이 없음 -> "학자금 대출이자 지원(시연 예시)" 1건 추가를 제안. 금액·일정은 넣지 않는다.
   - Supabase 연결 후에는 정책-항목 연결을 DB에서 읽는다(personal_fields_v0_3의 '필요 근거(정책후보ID)' 열이 원본).

## 4. 개인정보 규칙 (필수)

- 11개 입력값은 **React 컴포넌트 상태(메모리)에만** 둔다. localStorage, sessionStorage, IndexedDB, URL(해시·쿼리), console, 토스트 문구에 값을 남기지 않는다.
- 입력 영역에 "이 값은 저장되지 않아요. 새로고침하거나 다른 화면으로 가면 지워져요" 안내를 둔다.
- 금액(44, 45)은 판정에 필요한 범위만 받는다. 잔액·이자 금액은 받지 않는다(48, 54).

## 5. 완료 기준

- 정책 상세에서 해당 항목만 보이고, 각 항목에 서류·확인 내용·발급 경로·주의사항이 원본 CSV와 같은 문구로 나온다.
- 값을 입력하고 새로고침하면 사라진다. 입력 전후 localStorage·sessionStorage 키가 늘지 않는다(테스트로 확인).
- 전자지갑 화면에 14종이 지갑 연계 서류와 구분되어 나온다.
- `npm run lint`, `npm test`, `npm run build` 통과. 360·390·1280px에서 가로 넘침 없음.
- 테스트: (1) 11개 항목이 모두 14종 안의 서류를 1개 이상 가짐 (2) 직접 입력 값이 저장소에 쓰이지 않음 (3) 정책별 항목 연결.
