## 초안을 만든 근거

- `policy_candidates_v0_1.csv`의 대상 요약·거주 요건·중복 문구·출처 URL

- API 문구는 공고 원문이 아니다(`근거 위치`에 표시). 검수 때 공고 원문 문장으로 바꾼다.

## 검수 순서 (한 행씩)

1. `근거 URL`의 공고 원문을 연다. 2026 공고가 아니면 메모에 적고 최신 공고를 찾는다.
2. `값(JSON)`, `화면 문구`, `질문`, `선택지(JSON)`을 원문 기준으로 고친다. 원문에 없는 조건이면 `검수 상태`를 `반려`로.
3. `근거 원문 인용`을 원문 문장으로 바꾸고, `근거 위치`에 쪽·항목을 적는다.
4. `검수 상태` = `검수 완료`, `검수자` = 이름, `검수일` = YYYY-MM-DD.
5. 적재: `python pipeline/load_supabase.py --raw data_raw/policies_all.json --collected-on 2026-11-09`
   (검사에 걸리면 행 번호와 이유가 나온다. 적재 전 `--dry-run`으로 먼저 확인 가능)

`메모` 칸은 초안이 놓친 점이다. 검수할 때 먼저 읽는다.

## 규칙 모양 (화면 엔진 기준)

- 한 정책 안에서 `OR묶음` 값이 같은 행은 '하나만 맞으면 됨'. 묶음 안에서 AND는 못 쓴다.
- 그래서 '본인 또는 부모가 ○○시에 1년 이상'은 질문에 지역을 넣었다.
  예: `registered_move_in_date` 질문 "본인이 천안시에 계속 주민등록한 기간은?" / `parent_registered_duration` 질문 "부모(직계존속)가 천안시에 계속 주민등록한 기간은?"
- 한 정책에서 같은 항목ID는 입력 칸 하나를 같이 쓴다(G2의 `capital_area_commute`만 일부러 2행).
- `special_target_status`, `exam_info`, `graduation_date`, `hire_date`는 정책마다 질문을 다르게 썼다(공고별 일시 입력이라 정책마다 따로 답한다).
- 예외 대상이 많은 조건(B1 성적 예외, A1 대학원생 연령 등)은 X가 잘못 나올 수 있어 메모에 적어 두었다.

## 팀이 정할 것

1. B1: 기초·차상위(C학점), 장애인·자립준비청년(성적 기준 없음) 예외를 OR묶음으로 넣을지, 성적 행을 반려하고 ?로 둘지
2. B4: 장학금 유형이 4개라 한 공고키로는 정확하지 않다 → 유형별 공고키로 나눌지
3. 반려 권장 7행(A3 연령·소득분위·직장가입자, C4 연령, D3 연령·미취업, E4 연령)을 반려할지
4. C3: 공고가 출생연도(1986~2007년생) 기준이라 만 나이 규칙과 경계가 다르다
5. A1: 졸업학년은 이수학점 기준 적용 제외 → 졸업학년 예외를 넣을지
(해결됨: C3 일반 버팀목, F1 소득 0원, F2 50%/100%)

## 가상 지갑과의 관계

가상 인물 3명으로 엔진을 돌려 보면(초안을 검수 완료로 가정) 28개 정책이 대부분 O 또는 X로 갈린다.
다만 같은 항목ID라도 정책마다 질문이 달라서, 지갑에는 '질문의 답'이 아니라 '사실'(주소 이력, 부모 주소 이력, 학교·캠퍼스, 졸업 예정 연월, 직장 소재지·규모, 건강보험 자격 등)을 두고,
규칙의 질문마다 답을 계산하는 변환 단계가 필요하다.
